Portfolio-aware Event Triage

시장 이벤트를 모바일에서 빠르게 읽고, 내 보유/관심/관련 맥락과 확인 가능한 근거를 본 뒤, 더 깊게 볼 필요가 있는지 판단하도록 돕는 concept-level triage 화면입니다.

High-fidelity Design PASS Visual QA PASS Production BLOCKED

01 Problem and context

모바일은 이벤트를 깊이 분석하기 전에, 먼저 개인 관련성과 근거 한계를 정리해야 합니다.

이 화면의 목적은 투자 판단을 대신하는 것이 아니라, 이벤트가 어떤 자산과 연결되는지, 그 관계가 보유/관심/관련/미확인 중 무엇인지, 그리고 어떤 근거와 한계가 있는지 보여주는 것입니다.

무슨 Event인가?

이벤트 타입, 제목, 발생/기준 시점을 먼저 배치해 사용자가 맥락을 놓치지 않게 합니다.

내 맥락과 어떻게 연결되는가?

Holding, Watchlist, Related-only, Unconnected를 분리해 관심과 보유를 섞지 않습니다.

더 볼 근거가 있는가?

Source, timestamp, 요약 구분, 데이터 부족을 Outcome보다 먼저 읽게 합니다.

02 Product role split

Mobile은 Triage Layer, Web은 Analysis Workspace입니다.

모바일 화면은 깊은 재무표나 긴 리서치를 복제하지 않고, Event - Asset - Evidence - Handoff의 판단 전 구조를 압축해서 보여줍니다.

Mobile Triage Layer

Event Context, Asset Relationship, Portfolio/Watchlist Context, Evidence, non-advisory Outcome, Web Handoff entry.

Web Analysis Workspace

Deep analysis, documents, transcripts, advanced charts, longer research, detailed investment analysis.

03 Locked IA

04 Canonical screen anatomy

한 장의 모바일 Frame 안에서 사건, 관계, 근거, 다음 깊이를 순서대로 읽게 합니다.

Canonical state는 `CHECK_FURTHER + Holding + Evidence available + Concept Web Handoff`입니다.

1. Event Context이벤트 정체성과 기준 시점이 첫 화면의 시작점입니다.
2. Asset Relationship자산명, 티커, 관계 badge로 연결 대상을 분명히 합니다.
3. Portfolio / Attention Context보유, 관심, 관련, 미연결 상태를 서로 다른 의미로 다룹니다.
4. Evidence + TrustSource, timestamp, 요약 구분, 데이터 상태가 Outcome 앞에 놓입니다.
5. Relevance OutcomeOutcome은 근거 기반 check-status이며 권유나 점수가 아닙니다.
6. Web Handoff깊은 분석의 목적지만 설명하며 실제 route/payload는 확정하지 않습니다.

05 Three non-advisory outcomes

Outcome은 투자 행동이 아니라 확인 상태입니다.

의미는 label, copy, hierarchy, icon/shape, supporting evidence 순서로 전달하고 색은 보조 cue로만 사용합니다.

06 Portfolio context variants

Watchlist는 Holding이 아니고, Related-only는 개인 관계가 아닙니다.

Portfolio-aware 화면의 신뢰는 개인 맥락을 과장하지 않는 데서 시작합니다.

07 Trust and evidence states

불확실한 상태는 숨기지 않고 화면 구조 안에 남깁니다.

Partial, Empty, Stale, Source Unavailable, Permission, Error는 모두 다른 사용자의 해석을 만들기 때문에 같은 Empty로 묶지 않습니다.

08 Responsive screenshot QA evidence

320, 360, 390 viewport에서 hierarchy와 wrapping을 검증했습니다.

Screenshot은 장식이 아니라 QA evidence입니다. 첫 viewport, title/ticker/badge/source wrapping, sticky CTA overlap을 확인하는 기준으로 사용합니다.

10 Design-system mapping

Git reference system에서 토큰과 컴포넌트를 뽑아 화면에 연결했습니다.

이 디자인 시스템은 Valley 스타일을 참고한 모바일 설계용 reference입니다. Product policy나 Production 범위를 결정하지 않고, surface, type, badge, evidence, feedback, CTA 표현을 일관되게 유지하는 데 사용했습니다.

Surface
`--nf-surface-dashboard-mobile`, `--nf-surface-card`, `--nf-surface-card-muted` for phone background, cards, and evidence surfaces.
Typography
`--nf-font-sans`, `--nf-text-xs` to `--nf-text-xl`, and `--nf-weight-*` for Korean-first hierarchy and metadata density.
Relationship / data badges
Badge treatment from `badges-tabs-filters.md`; Holding, Watchlist, Related-only, and Unconnected remain text-led and separated.
Evidence / trust
Evidence Card pattern from `data-and-evidence.md`; summary, source, timestamp, system summary label, and data state appear before Outcome.
Feedback states
Loading, Empty, Stale, Source Unavailable, Permission, Error, and Handoff Failure reuse or adapt `feedback-states.md`.
CTA
Primary, disabled, and retry CTA behavior follows `buttons-and-cta.md`; handoff remains concept-level.
Pattern adaptation
`portfolio-aware-event-triage.md` is adapted where older first-viewport ordering conflicts with the locked Product IA.
